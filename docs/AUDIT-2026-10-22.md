# ED2K preview and release review — 2026-10-22

Baseline: `1a410627bd55edb0e5007f31f406896f2a134964` (CI #132), paired with ADM `89827de59344b0859935c26530c84edacb961686` (test build #161).

## Findings and fixes

1. Preview geometry selected the first and last parts, but helpers only joined them after all fresh parts were assigned. The supplied log shows the first part taking 179.6 seconds while middle parts completed. Helpers now claim unrequested header/tail blocks before continuing or opening middle parts. Stale requests use the existing timeout and duplicate-request bound. Failed mixed-source parts retain the single-owner retry rule.
2. ADM cleared its verified map on the initial Checking event of each automatic retry, briefly disabling an already available preview. ADM now preserves the current process's map during Checking and applies the fresh complete map afterwards. Explicit resume/restart still clears it.
3. The sample's 89.5% is 748,586,799 of 836,138,799 bytes. Its connected sources report no remaining parts. This evidence cannot establish that the downloader can obtain the final nine parts from the public network.
4. README/capability documentation still described four peers and exclusively owned parts. Current transfer code supports eight simultaneous peers and three-block requests with cooperative assembly. Documentation now matches that implementation.

## Upstream comparison

Read aMule master `6a1105634d81242a581a0f36a7e00379b12a83f3`, `src/PartFile.cpp`: `PreviewAvailable()` checks a received 256 KiB prefix. ## Scope and evidence

Focused manual review covered ED2K scheduling, authentication/write ordering, progress publication, ADM preview readiness/range serving, release packaging and current documentation. Repository-wide Rust tests, formatting and Clippy are the automated checks. This is not a claim that every line in both repositories has been manually audited or that every public peer/router works. Historical handoff files retain their original dated statements.

Regression tests cover cooperation before fresh middle parts, orphan recovery, corrupt sources, source arrival, verified read maps and missing-part diagnostics. Existing HTTP, RPC, torrent and protocol tests remain part of CI. Final platform-specific results are recorded by GitHub Actions for the release commit.
