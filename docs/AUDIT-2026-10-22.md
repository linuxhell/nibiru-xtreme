# ED2K preview and release review — 2026-10-22

Baseline: `1a410627bd55edb0e5007f31f406896f2a134964` (CI #132), paired with ADM `89827de59344b0859935c26530c84edacb961686` (test build #161).

## Findings and fixes

1. Preview geometry selected the first and last parts, but helpers only joined them after all fresh parts were assigned. The supplied log shows the first part taking 179.6 seconds while middle parts completed. Helpers now claim unrequested header/tail blocks before continuing or opening middle parts. Stale requests use the existing timeout and duplicate-request bound. Failed mixed-source parts retain the single-owner retry rule.
2. ADM cleared its verified map on the initial Checking event of each automatic retry, briefly disabling an already available preview. ADM now preserves the current process's map during Checking and applies the fresh complete map afterwards. Explicit resume/restart still clears it.
3. The sample's 89.5% is 748,586,799 of 836,138,799 bytes. Its connected sources report no remaining parts. This evidence cannot establish that the downloader can obtain the final nine parts from the public network.
4. README/capability documentation still described four peers and exclusively owned parts. Current transfer code supports eight simultaneous peers and three-block requests with cooperative assembly. Documentation now matches that implementation.

## Closing review

Idle BitTorrent TCP, uTP, DHT UDP and preview listeners could outlive their owner while waiting for new traffic. Listener tasks now observe an ownership stop signal; preview accepts use a weak owner reference and uTP receives its cancellation token. Regression tests rebind the TCP/UDP port after dropping each idle owner. The TCP and DHT regressions failed before the fix.

Only CI and Release workflows remain. CI produces one executable per platform, including only the EXE for Windows test artifacts; Release reuses those tested binaries rather than compiling them a second time. Linux release output remains static musl. Format, all-feature/all-target Rust tests and strict Clippy run locally and in platform CI; external interoperability runs on Linux CI.

The first closing CI run exposed a race in the independent libtorrent fixture: it read output immediately at is_seeding, before the independent client's asynchronous writes were guaranteed complete. The fixture now enables storage alerts, requests flush_cache and waits for cache_flushed_alert for the same torrent before comparing every byte. This follows libtorrent's documented persistence contract (https://www.libtorrent.org/reference-Torrent_Handle.html#flush-cache); payload equality remains mandatory. This change does not modify the engine's transfer implementation.

## Daily-use follow-up: HTTPS trust

The user's diagnostic bundle shows ADM 0.6.1 with Xtreme 0.2.0 failing NirSoft downloads before an HTTP response. It does not contain the nested transport cause. In this environment the same URL reproduced UnknownIssuer; enabling native trusted roots alongside bundled public roots allowed the exact three ZIPs to download via RPC, with CRC verification. This establishes the cause and correction here, not proof of the Windows machine's original certificate chain. TLS remains mandatory and invalid certificates/hostnames remain rejected; an isolated HTTPS regression checks all three cases. RPC now emits a safe certificate/connection category instead of discarding the underlying distinction.

A macOS CI failure compared wall-clock duration of separate 10 MB ED2K downloads under varying load. The regression now measures return latency from the first fully verified progress event, with silent metadata requests kept pending for 10 seconds. The 450 ms completion bound remains, without including transfer/hash CPU time.
