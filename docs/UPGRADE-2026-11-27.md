Baseline: 0.2.9 (`e563a924b6243497f92c964b9d2e644bdc54add9`).

Authorized scope: implement origin learning, automatic HTTP/3 with safe HTTP fallback,
native asynchronous disk I/O, BLAKE3 partial integrity, integrate the engine in ADM,
and publish verified releases. Expected gains must be measured; there is no universal
throughput guarantee.

## Implementation details

The protocol race allows QUIC a 75 ms head start, starts the TCP request on delay
or QUIC failure, and bounds the initial QUIC-header wait to two seconds. The
winner supplies the original payload response; later ranges and validators keep
that protocol. HTTP/1.1-only and explicit HTTP/3 remain available. Automatic QUIC
is skipped for explicit proxies and proxy environment variables, rather than
opening a direct connection around them. Certificate and hostname checks remain
mandatory. Extra TLS roots are accepted only when explicitly supplied.

Private origin profiles use hashed request context plus local route, 256 entries,
a 24-hour concurrency TTL and ten-minute transport TTL. Queries/credentials are
not stored. The profile is a hint, not an integrity or bandwidth guarantee.
Only completed, unthrottled samples of at least 64 MiB and four seconds are
learned. Adaptive exploration remains within the caller's ceiling; a small old
hint can grow after network capacity changes. CLI/RPC service directories hold
`.nibiru-profiles.json`; a bare library engine retains hints only in memory.
`--fixed-connections`, `--no-http3` and `--portable-io` isolate experiments.

Segmented HTTP writes use one completion runtime per transfer, bounded at 32
outstanding owned buffers. A reopened native handle is checked against the
original file identity. Native-unavailable systems fall back before writing.
Cancellation drains already-submitted writes before a resumable checkpoint;
Windows native handles close before publication. Final file sync and atomic
no-overwrite publication remain mandatory. Native I/O availability is logged;
compilation support alone does not prove that a restricted Linux kernel allows
io_uring. The crate retains `forbid(unsafe_code)`.

Partial state version 2 stores BLAKE3 per completed 4 MiB block. A previous
version is readable, but blocks without digests are downloaded again. Local
checksums run off the async executor with cancellation checks. The remote strong
validator must still match. This detects local corruption, not an attacker who
can replace both data and metadata. It does not replace a publisher's SHA-256.

## Validation and performance interpretation

Regression coverage includes exact HTTP/1 and HTTP/2 payloads, first-GET reuse,
TLS trust/hostname failures, stalled-QUIC fallback and loser cleanup, per-origin
limits, throttle recovery, state persistence/expiry, positional-write identity,
pause/kill/resume and actual on-disk block corruption. Existing torrent-selection
and protocol interoperability checks remain required in CI. Windows and macOS
native behavior is additionally validated by the three-platform workflow.

The earlier Windows ISO 84s ADM versus 93s IDM result was reported by the owner;
no new controlled Windows IDM measurement has been made in this environment.
Native disk support and HTTP/3 do not imply a speed gain on every machine.

### Controlled HTTP comparison, 27 November 2026

A 512 MiB synthetic localhost fixture, paced at 105 MiB/s with 40 ms artificial
request latency, ran three alternating rounds per release binary. All six
outputs matched SHA-256 `c047731a3c134f3d34286d608e9c173027d50f43ab9d2064f3c360939977e908`.
Median elapsed time: 0.2.9 5.049s; 0.3.0 candidate 4.979s. This small controlled comparison does not establish an Internet speed improvement. Both used portable I/O in the restricted Linux container; it does not measure IOCP or io_uring gains.
